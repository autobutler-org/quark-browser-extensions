# Dependencies and bundle size

Measured on 2026-10-14 from a clean `npm ci` of the lockfile (306 packages). Production builds are `wxt build -b chrome` and `wxt build -b firefox` (WXT 0.21.4, Vite 8.3.1). The JavaScript files are byte-identical between the two browsers; only the manifests differ (Chrome 990 bytes, Firefox 1,177). Gzip figures are `gzip -9`.

Module sizes inside a file come from the build's hidden sourcemaps: each source owns the generated bytes until the next mapping, counted as UTF-8. Those ranges add up to the file size.

The high advisory is [GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q) (CVE-2026-93749) in `source-map-js` 1.2.1. Through 1.2.1, an indexed source map with a huge per-section offset blocks the event loop. Fixed in 1.2.2. `npm audit fix --dry-run` changes that one package and nothing else. The parents already allow it: `postcss` 8.5.28, `css-tree` 3.2.1 (via `jsdom`), and `magicast` 0.5.5 (via `@vitest/coverage-v8`) all depend on `^1.2.1`.

It is not in the extension. Nothing under `src/` or `entrypoints/` imports it, and it does not appear in `.output/`. It is on the build (PostCSS) and test (jsdom, coverage) path only. (#92)

### What could be trimmed

Separate Vite production minifies of the same imports, not a second WXT build:

| Build | Raw | Gzip |
| --- | ---: | ---: |
| `parse` from `tldts/dist/index.esm.min.js` (what `host.ts` imports) | 118,766 | 43,760 |
| `parse` from the tree-shakeable `tldts` entry | 164,847 | 72,815 |
| Popup's `host.ts` imports only (`hostOf`, `isFallback`, `serverTransport`, and the other connect helpers; none call `parse`) | 119,918 | 44,355 |
| `frameMayFill` + `isFallback` (what the content script imports) | 127,634 | 46,588 |
| `upgradeLedger` only (what the popup imports from `authKey.ts`) | 6,041 | 2,969 |
| `deriveAuthKey` + `upgradeLedger` (what the worker needs) | 21,097 | 8,235 |

Switching `host.ts` to `import { parse } from "tldts"` does not shrink anything. The tree-shaken ESM build is 46,081 bytes larger raw and 29,055 bytes larger gzip than the prebuilt bundle, because the public-suffix trie minifies worse than the bundle tldts already ships. Keep the prebuilt file where `parse` is actually called.

The prebuilt file is still pulled in by imports that never call it. A bundle of only the popup's host helpers is 119,918 bytes, which is 1,152 more than the prebuilt tldts module on its own (118,766). The package has no `sideEffects: false`, so Rolldown keeps the whole minified module once `host.ts` is in the graph. That is why the popup and the options page preload the 131,470 byte chunk (gzip 48,042) even though their imports (`hostOf`, `isFallback`, `serverTransport`, `normalizeServer`, `searchEntries`, `needsInsecureConfirmation`) never touch the suffix list. Moving the tldts import into the module that calls `parse` (`hostMatches`, `frameMayFill`, `matchEntries`) takes that chunk off the popup and the options page. The background still needs it.

The content script keeps its own copy either way: it is one IIFE, and `frameMayFill` calls `parse`. That copy is the 126,558 bytes above. The worker runs the same match again before it returns credentials (`src/background/index.ts`), so the content-script copy is not the security boundary. Leaving the suffix test to the worker, and keeping a string check in the frame, would take the content script from 156,244 bytes down to about 29,686 (156,244 minus 126,558) and drop the second copy from the zip. (#94)

Argon2 has the same shape, at a smaller size. The popup imports `upgradeLedger` from `authKey.ts`, which only needs SHA-256 (`accountId`). `deriveAuthKey` (Argon2id + HKDF) is called from `src/shared/api.ts`, which only the service worker imports. Because both live in `authKey.ts`, the popup preloads the whole 21,167 byte chunk (gzip 8,274). A minify of `upgradeLedger` alone is 6,041 bytes (gzip 2,969); adding `deriveAuthKey` makes it 21,097 (gzip 8,235). A dynamic `import()` of `@noble/hashes/argon2.js` and `hkdf.js` inside `deriveAuthKey`, or moving that function to its own module, takes about 15,056 bytes (gzip 5,266) off every popup open. The zip keeps the code either way. The background would load it on sign-in instead of at worker startup. (#93)

## CI supply chain

No workflow in this repo pins an action to a commit SHA. `release.yml` and `check.yml` both use floating major tags, and `renovate.json` tracks `github-actions`. Pinning to a SHA would be a new convention, so this audit does not ask for it.

The two workflows are not on the same majors. Tags below are what was current on 2026-10-14.

| Action | `check.yml` | `release.yml` | Latest |
| --- | --- | --- | --- |
| `actions/checkout` | v4 | v7 | v7.0.1 |
| `actions/setup-node` | v4 | v7 | v7.1.0 |
| `actions/upload-artifact` | v4 | v7 | v7.0.2 |
| `actions/setup-go` | v5 | — | v7.0.0 |
| `actions/download-artifact` | — | v8 | v8.0.2 |

`check.yml` is the one behind. (#96) It also runs `npm run lint:firefox`, whose script is `npx --yes web-ext@8`. That installs whatever the `8` dist-tag points at (8.10.0 on this date) outside the lockfile, on every check. WXT 0.21.4's optional peer is `web-ext >= 9.2.0`. Current web-ext is 10.7.0. (#95) `npx wxt` and `npx playwright` in the workflows resolve to the copies `npm ci` installed. The Quark checkout is pinned: `QUARK_REF` falls back to `7a2e6688a62c891ea79caafabdd683503d202754`.

## Permissions

Both workflows set `permissions: contents: read` and no job widens it. Checkout needs that read. `upload-artifact` and `download-artifact` do not need `contents: write`. The release job submits with store secrets, not with `GITHUB_TOKEN`, and it does not create a GitHub release. There is no `id-token`, `packages`, `pull-requests`, or `actions: write`. This is already least privilege.

## Checked and fine

- Production install has no advisory and no duplicate packages.
- No direct dependency is unused.
- The dev duplicate versions are tooling nested under jsdom, Vitest, ESLint and `@puppeteer/browsers`. They are not worth a dedupe.
- The tree-shakeable `tldts` entry is larger than the prebuilt bundle. The waste is that every importer of `host.ts` keeps the prebuilt file, not that the file itself should be replaced.
- Action SHAs are not how this repo pins CI. The gap is `check.yml` still being on v4/v5 while `release.yml` is on v7/v8.
- Token permissions are already `contents: read`.
